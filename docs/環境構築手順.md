# Spring Petclinic（React）環境構築手順

この手順は、ホストに JDK と Node.js を入れず、Docker だけで API と React 画面を起動する手順です。データベースの初期状態は API コンテナ内の HSQLDB（メモリ）です。

## 1. 前提

| 項目 | 内容 |
| --- | --- |
| OS | Ubuntu 22.04（WSL2） |
| 必要なもの | Docker Engine（Community）と Docker Compose プラグイン |
| ホストに不要なもの | JDK、Maven、Node.js、npm |
| 画面 | http://localhost:4444 |
| API | http://localhost:9966/petclinic/ |

確認コマンド:

```bash
docker version
docker compose version
```

`docker: command not found` と出る場合は、次の「Docker Engine のインストール」を先に行います。

### Docker Engine のインストール（未導入の場合）

Ubuntu 22.04（WSL2）に Docker Engine（Community）を入れる手順です。Docker 公式のリポジトリから `docker-ce` を取得します。コマンドは `sudo` を使うため、パスワードを求められます。

1. 既存の Docker 関連パッケージを削除します。入っていなければ何も起きません。

    ```bash
    for pkg in docker.io docker-doc docker-compose docker-compose-v2 podman-docker containerd runc; do
      sudo apt-get remove -y $pkg
    done
    ```

2. Docker 公式の APT リポジトリを登録します。

    ```bash
    sudo apt-get update
    sudo apt-get install -y ca-certificates curl
    sudo install -m 0755 -d /etc/apt/keyrings
    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
    sudo chmod a+r /etc/apt/keyrings/docker.asc

    sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
    Types: deb
    URIs: https://download.docker.com/linux/ubuntu
    Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
    Components: stable
    Architectures: $(dpkg --print-architecture)
    Signed-By: /etc/apt/keyrings/docker.asc
    EOF

    sudo apt-get update
    ```

3. Docker Engine、CLI、Buildx、Compose プラグインをインストールします。

    ```bash
    sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    ```

4. デーモンを起動します。WSL2 で systemd を使っていない場合は次を実行します。

    ```bash
    sudo service docker start
    ```

    systemd が有効な場合は、起動と自動起動をまとめて設定します。

    ```bash
    sudo systemctl enable --now docker
    ```

5. 動作確認をします。

    ```bash
    sudo docker run --rm hello-world
    ```

    `Hello from Docker!` が表示されれば成功です。

### docker グループへの追加

`docker version` の Server 欄で `permission denied` と出る場合は、現在のユーザーが `docker` グループに入っていません。

```bash
sudo usermod -aG docker "$USER"
newgrp docker
```

`newgrp` の代わりに、WSL のターミナルを開き直しても構いません。`id` の結果に `docker` が含まれていれば反映されています。

## 2. アプリケーションの起動

リポジトリのルートで実行します。

```bash
cd ~/spring-petclinic
docker compose up --build
```

初回は API の Maven ビルドと、React の npm インストールおよび webpack ビルドが走るため、完了まで数分かかります。API のログに起動完了が出て、画面用コンテナが待ち受けたら使えます。

ブラウザで http://localhost:4444 を開きます。

API の確認例:

```bash
curl http://localhost:9966/petclinic/api/pettypes
```

## 3. 開発用コンテナ

ソースを編集しながら動かす場合は、JDK と Node.js もコンテナの中で動かします。ホストへのインストールは不要です。`src` と `client/src` はコンテナにマウントされるので、保存すると反映されます。

確認用のコンテナが動いているときは、先に止めます。ポート `4444` と `9966` を共有しているためです。

```bash
docker compose down
docker compose -f docker-compose.dev.yml up --build
```

画面は http://localhost:4444 、API は http://localhost:9966/petclinic/ です。

- Java を保存すると、コンテナ内で再コンパイルされ、API が再起動します。反映まで十数秒かかることがあります。
- `client/src` を保存すると、webpack が再ビルドし、ブラウザを開き直すと反映されます。
- `pom.xml` や `client/package.json` を変えたときは、同じコマンドでイメージを作り直します。

### 3.1 VS Code / Cursor のコンテナで開く（Reopen in Container）

`.devcontainer/devcontainer.json` を用意しています。エディタからこのフォルダを開き、コマンドパレットで次のどちらかを実行します。

- `Dev Containers: Reopen in Container`（コンテナに入り直す）
- `Dev Containers: Rebuild and Reopen in Container`（イメージから作り直して入る）

コンテナ内の `/workspace` がこのフォルダに対応します。`backend` のコンテナで開き、`frontend` も同時に起動します。前提として、Dev Containers 拡張機能が必要です。`Reopen in Container` の操作は、エディタ側の画面からのみ行えます。コマンドラインでは、上の `docker compose -f docker-compose.dev.yml up --build` で同じ環境を起動できます。

止めるときは `Ctrl+C` のあと、次を実行します。

```bash
docker compose -f docker-compose.dev.yml down
```

## 4. 構成

| コンテナ | イメージ内の主なソフトウェア | ホストのポート |
| --- | --- | --- |
| backend | Eclipse Temurin 17、Maven でビルドした Spring Boot | 9966 |
| frontend | Node.js 18 でビルドし、nginx で静的ファイルを配信 | 4444 |

画面の JavaScript は、ブラウザから `http://localhost:9966/petclinic` を直接呼びます。この URL はフロントのイメージを作るときに埋め込みます。API の CORS は `http://localhost:4444` からのアクセスを許可しています。

## 5. 停止

起動したターミナルで `Ctrl+C` を押します。コンテナを消す場合は次を実行します。

```bash
docker compose down
```

HSQLDB のデータはメモリ上だけなので、API コンテナを止めると消えます。

## 6. コードを変えたあとの再ビルド

```bash
docker compose up --build
```

画面から呼ぶ API の URL を変える場合は、`docker-compose.yml` の `frontend.build.args.API_SERVER_URL` を変えてから、同じコマンドで作り直します。ブラウザから到達できる URL にしてください。

## 7. うまくいかないとき

**`permission denied` で Docker に接続できない**

「docker グループへの追加」を実行し、ターミナルを開き直してください。

**`4444` または `9966` が使用中**

別のプロセスがポートを使っています。`docker-compose.yml` の ports の左側だけを変えます。画面のポートを変えた場合は、API が許可するオリジンも合わせて変えます。

```yaml
backend:
  environment:
    PETCLINIC_CORS_ALLOWED_ORIGINS: http://localhost:4445
```

プロパティ名は `petclinic.cors.allowed-origins` です。画面側の `API_SERVER_URL` も、変えた API ポートに合わせてビルドし直します。

**画面は開くがデータが取れない**

ブラウザのアドレスが `http://localhost:4444` であることを確認します。`127.0.0.1` で開くと、API が許可しているオリジンと一致しません。
