# Spring Petclinic（React）環境構築手順

この手順は、ホストに JDK と Node.js を入れず、Docker だけで API と React 画面を起動する手順です。データベースの初期状態は API コンテナ内の HSQLDB（メモリ）です。

## 1. 前提

| 項目 | 内容 |
| --- | --- |
| OS | Ubuntu 22.04（WSL2） |
| 必要なもの | Docker Engine（Community・28 系推奨）と Docker Compose プラグイン |
| ホストに不要なもの | JDK、Maven、Node.js、npm |
| 画面 | http://localhost:4444 |
| API | http://localhost:9966/petclinic/ |

> **注意（Docker 29 系と Dev Containers の互換性について）:**
> Docker Engine 29 系ではイベント JSON の仕様変更により、VS Code / Cursor の Dev Containers 拡張がコンテナ新規作成時の起動検知で停止することがあります。Dev Containers を利用する場合は **Docker 28 系** の使用を推奨します。

確認コマンド:

```bash
docker version
docker compose version
```

`docker: command not found` と出る場合は、次の「Docker Engine のインストール」を先に行います。

### Docker Engine のインストール（未導入・バージョン調整の場合）

Ubuntu 22.04（WSL2）に Docker Engine（Community）を入れる手順です。Docker 公式のリポジトリから `docker-ce` を取得します。コマンドは `sudo` を使うため、パスワードを求められます。

1. 既存の Docker 関連パッケージを削除します（新規導入の場合、入っていなければ何も起きません）。

   ```bash
   for pkg in docker.io docker-doc docker-compose docker-compose-v2 podman-docker containerd runc; do
     sudo apt-get remove -y $pkg
   done
   ```

2. Docker 公式の APT リポジトリを登録します。

   ```bash
   sudo apt-get update
   sudo apt-get install -y ca-certificates curl
   sudo install -m 0755 -d /etc/apt/keyrings
   sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
   sudo chmod a+r /etc/apt/keyrings/docker.asc

   sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
   Types: deb
   URIs: https://download.docker.com/linux/ubuntu
   Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
   Components: stable
   Architectures: $(dpkg --print-architecture)
   Signed-By: /etc/apt/keyrings/docker.asc
   EOF

   sudo apt-get update
   ```

3. インストール可能なバージョンを確認し、Docker 28 系（例: `5:28.5.2-1~ubuntu.22.04~jammy`）を指定してインストールします。

   ```bash
   apt-cache madison docker-ce

   VERSION="5:28.5.2-1~ubuntu.22.04~jammy"
   sudo apt-get install -y --allow-downgrades \
     docker-ce="${VERSION}" \
     docker-ce-cli="${VERSION}" \
     containerd.io \
     docker-buildx-plugin \
     docker-compose-plugin
   ```

   意図しない 29 系への自動アップグレードを防ぐ場合は、バージョンを固定します。

   ```bash
   sudo apt-mark hold docker-ce docker-ce-cli
   ```

4. デーモンを起動します。WSL2 で systemd を使っていない場合は次を実行します。

   ```bash
   sudo service docker start
   ```

   systemd が有効な場合は、起動と自動起動をまとめて設定します。

   ```bash
   sudo systemctl enable --now docker
   ```

5. 動作確認をします。

   ```bash
   sudo docker run --rm hello-world
   ```

   `Hello from Docker!` が表示されれば成功です。

### docker グループへの追加

`docker version` の Server 欄で `permission denied` と出る場合は、現在のユーザーが `docker` グループに入っていません。

```bash
sudo usermod -aG docker "$USER"
newgrp docker
```

`newgrp` の代わりに、WSL のターミナルを開き直しても構いません。`id` の結果に `docker` が含まれていれば反映されています。

## 2. アプリケーションの起動

リポジトリのルートで実行します。

```bash
cd ~/spring-petclinic
docker compose up --build
```

初回は API の Maven ビルドと、React の npm インストールおよび webpack ビルドが走るため、完了まで数分かかります。API のログに起動完了が出て、画面用コンテナが待ち受けたら使えます。

ブラウザで http://localhost:4444 を開きます。

API の確認例:

```bash
curl http://localhost:9966/petclinic/api/pettypes
```

## 3. 開発用コンテナ

ソースを編集しながら動かす場合は、JDK と Node.js もコンテナの中で動かします。ホストへのインストールは不要です。`src` と `client/src` はコンテナにマウントされるので、保存すると反映されます。

確認用のコンテナが動いているときは、先に止めます。ポート `4444` と `9966` を共有しているためです。

```bash
docker compose down
docker compose -f docker-compose.dev.yml up --build
```

画面は http://localhost:4444 、API は http://localhost:9966/petclinic/ です。

- Java を保存すると、コンテナ内で再コンパイルされ、API が再起動します。反映まで十数秒かかることがあります。
- `client/src` を保存すると、webpack が再ビルドし、ブラウザを開き直すと反映されます。
- `pom.xml` や `client/package.json` を変えたときは、同じコマンドでイメージを作り直します。

### 3.1 VS Code / Cursor のコンテナで開く（Reopen in Container）

`.devcontainer/devcontainer.json` を用意しています。エディタからこのフォルダを開き、コマンドパレットで次のどちらかを実行します。

- `Dev Containers: Reopen in Container`（コンテナに入り直す）
- `Dev Containers: Rebuild and Reopen in Container`（イメージから作り直して入る）

コンテナ内の `/workspace` がこのフォルダに対応します。`backend` のコンテナで開き、`frontend` と **`mcp-server`** も同時に起動します。前提として、Dev Containers 拡張機能が必要です。`Reopen in Container` の操作は、エディタ側の画面からのみ行えます。コマンドラインでは、上の `docker compose -f docker-compose.dev.yml up --build` で同じ環境を起動できます。

> **Dev Containers の起動が途中で止まる場合:**
> Docker 29 系などの環境でコンテナ作成後に接続待ちのまま進まない場合は、一度ウィンドウを閉じてから、Rebuild ではなく通常の **`Dev Containers: Reopen in Container`** を実行してください。作成済みのコンテナへ直接接続できます。

止めるときは `Ctrl+C` のあと、次を実行します。

```bash
docker compose -f docker-compose.dev.yml down
```

### 3.2 Cursor から MCP を接続して手動テストする

MCP サーバーは Dev Container 起動時に `mcp-server` コンテナとして立ち上がります。Cursor の MCP クライアントは **ホスト側** で動くことが多いため、接続 URL は `http://localhost:8090/mcp` です（リポジトリ直下の `.cursor/mcp.json` に記載済み）。

1. **Dev Container でプロジェクトを開く**（3.1 のとおり）。`backend`・`frontend`・`mcp-server` が起動していることを確認します。

   Dev Container **内**のターミナルでは `docker` コマンドは使えません（`backend` イメージに CLI がないため）。コンテナ内では次で疎通だけ確認できます。

   ```bash
   curl -s -o /dev/null -w "api %{http_code}\n" http://localhost:9966/petclinic/api/pettypes
   curl -s -o /dev/null -w "mcp %{http_code}\n" http://mcp-server:8090/mcp
   ```

   コンテナ一覧を見る場合は、**ホスト**（WSL など Dev Container の外）で `docker compose -f docker-compose.dev.yml ps` を実行してください。

2. **Cursor Settings → MCP** を開き、サーバー名 **`petclinic`** が表示され、接続済みであることを確認します。表示されない場合は **Reload Window** してください。

3. **ツールを試す**（MCP パネルから直接実行するか、チャットで依頼）:
   - `list_pet_types` … 6 種類のペット種別
   - `list_owners`（`lastName`: `Davis`）… 飼い主が複数ヒット
   - `get_owner`（`ownerId`: `1`）… George Franklin / ペット Leo
   - `get_owner`（`ownerId`: `999`）… 見つからない旨のエラー

4. **照合**: ブラウザで http://localhost:4444 を開き、上記と同じ内容が画面に出るか確認します。

詳細な手順とトラブルシュートは [mcp-server/README.md](../mcp-server/README.md) の「Cursor から接続して手動テストする」を参照してください。JSON-RPC とログの対応は [mcp-server/docs/CursorとMCPのやり取り.md](../mcp-server/docs/CursorとMCPのやり取り.md) です。

### 3.3 ログの確認（MCP / API / 画面）

コンテナのログは標準出力に出ます。**`docker compose logs` は Dev Container の外（WSL ホストなど）で実行**してください。コンテナ内のターミナルでは `docker` は使えません。

```bash
# リポジトリ直下（ホスト側）
docker compose -f docker-compose.dev.yml logs -f mcp-server
docker compose -f docker-compose.dev.yml logs --tail=100 backend
docker compose -f docker-compose.dev.yml logs -f backend frontend mcp-server
```

Cursor では、ホスト用ターミナル（**Local** プロファイル）を開いて上記を実行するか、Docker 拡張機能のコンテナ一覧から **Logs** を開きます。

MCP サーバー側の API 呼び出しまわりの詳細ログは、既定で `DEBUG` レベルです。項目ごとの説明は [mcp-server/README.md](../mcp-server/README.md) の「ログの確認」を参照してください。

## 4. 構成

| コンテナ | イメージ内の主なソフトウェア | ホストのポート |
| --- | --- | --- |
| backend | Eclipse Temurin 17、Maven でビルドした Spring Boot | 9966 |
| frontend | Node.js 18、webpack dev server | 4444 |
| mcp-server | Java 17、Spring AI MCP（REST API ラッパー） | 127.0.0.1:8090 |

画面の JavaScript は、ブラウザから `http://localhost:9966/petclinic` を直接呼びます。この URL はフロントのイメージを作るときに埋め込みます。API の CORS は `http://localhost:4444` からのアクセスを許可しています。

## 5. 停止

起動したターミナルで `Ctrl+C` を押します。コンテナを消す場合は次を実行します。

```bash
docker compose down
```

HSQLDB のデータはメモリ上だけなので、API コンテナを止めると消えます。

## 6. コードを変えたあとの再ビルド

```bash
docker compose up --build
```

画面から呼ぶ API の URL を変える場合は、`docker-compose.yml` の `frontend.build.args.API_SERVER_URL` を変えてから、同じコマンドで作り直します。ブラウザから到達できる URL にしてください。

## 7. うまくいかないとき

**`permission denied` で Docker に接続できない**

「docker グループへの追加」を実行し、ターミナルを開き直してください。

**`./mvnw` や `.sh` 実行時に `Syntax error` が出る**

Windows 側で編集・コピーした影響で改行コードが `CRLF` になっている可能性があります。対象ファイル（`mvnw`、`docker/backend-dev.sh` など）の改行コードを `LF` に変換してから再ビルドしてください。

**`4444` または `9966` が使用中**

別のプロセスがポートを使っています。`docker-compose.yml` の ports の左側だけを変えます。画面のポートを変えた場合は、API が許可するオリジンも合わせて変えます。

```yaml
backend:
  environment:
    PETCLINIC_CORS_ALLOWED_ORIGINS: http://localhost:4445
```

プロパティ名は `petclinic.cors.allowed-origins` です。画面側の `API_SERVER_URL` も、変えた API ポートに合わせてビルドし直します。

**画面は開くがデータが取れない**

ブラウザのアドレスが `http://localhost:4444` であることを確認します。`127.0.0.1` で開くと、API が許可しているオリジンと一致しません。
