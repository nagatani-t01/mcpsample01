# 1

リポジトリの現状を確認し、MCP連携の導入方針を整理してください。まだコードや設定ファイルは変更しないでください。

対象として確認してほしいファイル:
- @docker-compose.yml
- @docker-compose.dev.yml
- @src/main/resources/openapi.yml （または @src/main/java/org/springframework/samples/petclinic/rest/controller/ 配下）

出力してほしいこと:
1. 既存のREST APIエンドポイント一覧（Owner / Pet / PetType / Vet / Visit など）の要約
2. MCPサーバー構成案（独立サービス `mcp-server/` として追加する案と、Spring Boot に組み込む案の比較と推奨案）
3. 最初に実装する最小限のツール（Tools）とリソース（Resources）の候補（まずは読み取り系中心、作成・更新系は段階追加を想定）
4. トランスポート方式（stdio / HTTP 等）の推奨案


# 2

先ほどの方針に基づき、MCPサーバーの最小プロトタイプを作成してください。
他の既存ファイルはできるだけ変更せず、MCPサーバー用のディレクトリ（例: `mcp-server/`）内に完結させてください。

要件:
- 既存のPetclinic REST APIを呼び出すクライアント処理を実装する
- まずは読み取り系ツール（例: Owner一覧/取得、Vet一覧、PetType一覧など）を中心に実装する
- エラー時（HTTPエラーや接続失敗時）に分かりやすいメッセージを返すようにする
- 起動方法と簡単な動作確認手順を短いメモ（`mcp-server/README.md` など）にまとめる

作業後、作成したファイル一覧と起動コマンドだけを簡潔に報告してください。


# 3

`mcp-server/` の実装を確認し、必要な操作ツールとエラーハンドリングを追加してください。
対象は `mcp-server/` 配下と、参照する既存コントローラー（必要なものだけ）に限定してください。

要件:
- 作成・更新系などのツールを追加する（既存のAPI仕様・バリデーションに合わせる）
- API側のエラーレスポンスやステータスコードを分かりやすく整形して返す
- 既存コードへの不要な変更は行わない

変更したファイルと追加したツール一覧を簡潔にまとめてください。


# 4

MCPサーバーをDocker環境およびエディタから利用しやすいように設定を整えてください。
変更対象は以下に限定してください:
- @docker-compose.dev.yml （または専用のMCP用composeファイル）
- @.devcontainer/devcontainer.json （必要な場合のみ）
- MCPクライアント設定例（例: `.cursor/mcp.json` または手順書内の設定例）

要件:
- バックエンドAPIとの接続先（ホスト/ポートやコンテナネットワーク）が分かりやすく設定できること
- 既存の `backend` / `frontend` / Dev Container 起動フローを壊さないこと

変更内容と起動・接続手順を簡潔に報告してください。
