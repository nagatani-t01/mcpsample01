# Spring Petclinic（React）MCP 連携導入計画書

本ドキュメントは、`mcpsample01`（Spring Boot バックエンド API ＋ React/TypeScript フロントエンド ＋ Docker Compose / Dev Container 構成の Petclinic アプリケーション）に対して、**MCP（Model Context Protocol）連携機能**を段階的に導入するための計画書です。

---

## 1. アーキテクチャ方針の選定

既存の Spring Boot API・React フロントエンド・Docker Compose 構成に MCP を組み込むにあたり、主に以下の 2 つのアプローチから方針を決定します。

| 項目 | 方式 A：独立した MCP サーバーを追加（推奨） | 方式 B：Spring Boot 内に MCP を組み込む |
| --- | --- | --- |
| **概要** | `mcp-server/` を新設し、既存の Petclinic REST API を呼び出すラッパーとして構築する | 既存の Spring Boot アプリ内で `ClinicService` 等を MCP ツールとして直接公開する |
| **メリット** | 既存のバックエンド・フロントエンド・Dev Container 構成への影響が最小限で、単体起動やデバッグが容易 | コンテナ数が増えず、内部サービス層へ直接アクセスできる |
| **考慮点** | API 経由での通信（HTTP）が発生する | 既存の `pom.xml` の依存関係や `security/` 設定との整合調整が必要 |

> **推奨方針:** まずは既存アプリへの影響を最小限に抑えられる **方式 A（独立した MCP サーバー）** から着手し、必要に応じて統合を検討します。

### 結論：下記の内容で進める
- `mcp-server/` を新設し、既存の Petclinic REST API を呼び出すラッパーとして構築する

## 2. 段階的な導入計画（4フェーズ）

### フェーズ 1：現状確認と MCP 仕様・スコープの定義
1. **既存 API / ドメインの棚卸し**
   - `src/main/resources/openapi.yml` および `src/main/java/org/springframework/samples/petclinic/rest/controller/` 配下（`OwnerRestController`、`PetRestController`、`PetTypeRestController`、`VetRestController`、`VisitRestController` など）を確認し、MCP から操作・参照させる対象を定義します。
   - 初期フェーズでは **読み取り系（Owner 検索、Vet 一覧、PetType 一覧、Visit 確認など）** から実装し、その後作成・更新系や削除系のツールを段階的に追加します（破壊的操作は誤操作防止のため慎重に設計）。
2. **トランスポート方式の決定**
   - ローカルの AI エディタ（Cursor / VS Code 等）から直接プロセス起動する場合は **`stdio`** を採用します。
   - Docker ネットワーク上の別コンテナや外部クライアントから接続する場合は **HTTP / SSE（または Streamable HTTP）** を採用します。

## 3. 実装着手前の確認事項

具体的な実装に進むにあたり、以下の 3 点を確定させます。

1. **アーキテクチャ方式**: 独立サービス（`mcp-server/`）として構築するか、既存 Spring Boot アプリ内に組み込むか。
→ 独立サービス（`mcp-server/`）として構築します

2. **接続元クライアント**: Cursor / VS Code などのローカル MCP クライアント（`stdio`）を主対象とするか、コンテナ間・外部 HTTP 接続も対象とするか。
→ コンテナ間・外部 HTTP 接続も対象とします。

3. **実装言語・ランタイム**: TypeScript（Node.js・既存 `client/` と同系技術）または Java（Spring AI MCP・既存バックエンドと同系技術）のどちらを採用するか。
→ Java（Spring AI MCP・既存バックエンドと同系技術）を採用します
